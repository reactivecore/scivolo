# ADR 0045 — Native intrinsics: types kept beside erasure, link-time conditions by tree shape

Status: accepted · Date: 2026-10-26

## Context
nscplugin generates Scala Native's intrinsics inline (#168, research 36 G4). Some need types
erasure drops: `sizeOf[T]`, `alignmentOf[T]`, `stackalloc[T]` and `CFuncPtrN.apply` need `T`
and the argument and result types as written. nscplugin keeps them as tree attachments made
by `PostInlineNativeInterop` after inlining; the typed trees of the lowering have no
attachments, and erasure drops the `TypeApply` nodes that hold the type arguments. Link-time
conditions (`if LinktimeInfo.isLinux`) become `linktime if` instructions; nscplugin recognizes
them in `genIf` from the shapes of erased trees (`getLinktimeCondition`).

## Decision
- A phase run right after `drop_inlined` (`phases/native_interop.rs`) records the types in
  `Lower::non_erased`, keyed by the method reference of the call, with the span of the type
  application. Erasure rewrites trees in place, so the reference keeps its id; the code
  generator refuses an intrinsic whose entry is missing rather than guessing a type.
- Link-time conditions stay `If` trees through the lowering; the code generator matches the
  shapes nscplugin matches (`codegen/linktime.rs`) and refuses a condition mixing link-time and
  run-time parts. Methods defining link-time values are generated by `codegen/linktime_defs.rs`.
- The intrinsics are the Scala Native backend's: dispatch, layouts and the recorded types live
  in `crates/lower`; the typer and namer know nothing of them (ADR 0043).

## Consequences
- No new tree kind and no change to erasure; a phase that copies a method reference without
  carrying its entry makes the call refused, not wrong.
- A JVM or JS backend ignores `non_erased`; a backend needing other unerased types adds its
  entries in the same phase.
